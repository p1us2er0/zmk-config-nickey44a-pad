# Nickey44A-PAD: このフォークのカスタマイズ

nixiy/zmk-config-nickey44a-pad をフォークし、作者の e3004b7（2026-10-19）の
上に加えた変更をまとめる。キーマップは tomkey のキーマップを元にしている。
変更ごとの詳しい理由は、各コミットのメッセージに書いてある。

## ビルドと書き込み

`scripts/build.sh` は、GitHub Actions と同じ ZMK v0.3（Zephyr 3.5）の
Dockerイメージを使って、手元でビルドする。`.uf2` とログは `build/` に出る。

```sh
scripts/build.sh nickey44a_r   # 右手
scripts/build.sh nickey44a_l   # 左手
scripts/build.sh               # build.yaml のすべて
```

書き込むときは、XIAOのリセットボタンを2回押すか、FUNCTION_BTレイヤーの
Bootキー（下の「Reset と Boot」）でブートモードにし、表示された
`XIAO-BOOT` に `.uf2` をコピーする。

`build.yaml` の `snippet` や `cmake-args` を消したときは、ビルド用の
Dockerボリュームにある古い設定が残るので、そのターゲットのビルド
ディレクトリを消してから作り直す。

```sh
docker run --rm -v nickey44a-zmk-ws:/ws zmkfirmware/zmk-build-arm:3.5 rm -rf /ws/build/nickey44a_r
```

ZMK Studioは使わないので、右手のビルドから外した（キーマップはgitで
管理する）。

右手がcentral。キーマップもトラックパッドの処理も右手で行うため、
キーマップやジェスチャを変えたときは右手だけ書き込めばよい。左手は、
左手の `.conf`・overlay や、左右両方に入る機能（ソフトオフなど）を
変えたときに書き込む。左手は2026-11-21（e8feeed）から、作者のFWではなく
このリポジトリのFWで動いている。

## キーマップ

tomkeyのレイヤー、コンボ、マクロ、behaviorを移植した。今のキーマップは
READMEの図（`keymap-drawer/nickey44a.svg`）で見られる。MOUSE_SLOW、IPAD、ANDROIDは、
キーを変えずトラックパッドの動きだけを変えるので、図には入れていない。

### レイヤー

| 番号 | 名前 | 内容 |
|---|---|---|
| 0 | MAC | Mac用の基本レイヤー |
| 1 | MOUSE_SLOW | すべて透過。右パッドを遅くし、2本指の左右スワイプを戻る / 進むにする |
| 2 | WIN | Windows用。MACに重ねて、左外側の中と下をWinとCtrlにする |
| 3 | WIN_JIS | Windows（JIS）用。WINと一緒に有効になり、JISで記号が違う5キーだけを持つ |
| 4 | IPAD | iPadの目印。中身は空 |
| 5 | ANDROID | Androidの目印。中身は空。WINと一緒に有効になる |
| 6 | NUM | 数字と記号。左親指のLANG2を長押し |
| 7 | FUNCTION_BT | Fキー、BTプロファイル、画面キャプチャ、電池残量。`;` を長押し |
| 8 | MOUSE | マウス操作。右親指のLANG1を長押し |
| 9 | AUTO_MOUSE | 右パッドに触れると有効になる |
| 10 | SYSTEM | Reset、Boot、電源オフ、BT_CLR。`;` とLANG2を両方押している間 |

WIN、WIN_JIS、IPAD、ANDROIDは、つないでいる機器の種類を表す目印で、FUNCTION_BTの
BTプロファイルのキーで切り替わる。

| プロファイル | 機器 | 有効になる目印 |
|---|---|---|
| BT0 | Mac | なし |
| BT1 | iPad | IPAD |
| BT2 | Android | WINとANDROID |
| BT3 | Windows | WIN |
| BT4 | Windows（JIS） | WINとWIN_JIS |
| BT5 | Mac（2台目） | なし |
| BT6 | iPad（2台目） | IPAD |

ZMKのBTプロファイルは、初期設定では5つ（接続の枠6つのうち1つを左手が
使う）。`nickey44a_r.conf` の `CONFIG_BT_MAX_PAIRED` と `CONFIG_BT_MAX_CONN` を
8にして、7つにしている。1つ増やすごとにRAMを約1 KB使う（256 KB中、今は
約63 KB）。プロファイルの数そのものでは電池は減らない。電池に効くのは、
同時につながっている機器の数で、ZMKはプロファイルを切り替えても前の機器との
接続を切らないので、近くで電源が入っている機器が多いほど、つなぎ続ける分の
電波を少しずつ使う。

JISのWindowsでもWINを有効にするので、WinとCtrlの入れ替えやWindows用の
ショートカットはWINだけに書けばよく、WIN_JISにはJISで記号が違うキー
（`;` `'` `,` `.` `-`）だけが残る。NUMより下に置いて、NUMのキーが
WIN_JISのキーに負けないようにしている。

AndroidのショートカットはWindowsと同じくCtrlを使うので、BT2ではWINも有効に
する。左外側の下がCtrl、中がMeta（Win）になり、ショートカットのキーも
Windowsと同じになる。ANDROIDには、Windowsと違うところだけを書く。

- 左パッドの2本指の左右（仮想デスクトップ）：Androidにはないので、何もしない。
- MOUSEのC / V：ホーム画面（`Meta+H`）と直前のアプリ（`Alt+Tab`）。
- モニターは切り替えない（F18 / F19を送らない）。
- LEDは、iPadと同じく消えたままにする。

`Alt+Tab` のアプリの切り替えは、Android 14以降のタブレットで使える。
右パッドのピンチはWindowsと同じキー（`Ctrl` + テンキーの `+` / `-`、`Ctrl+0`）を
送るが、Android版のChromeはキーボードでの拡大・縮小に対応していないという
報告があり、効かない見込み（拡大はメニューの「ズーム」か画面のピンチで行う）。
LANG1 / LANG2での入力の切り替えも、Androidで効くかをまだ確かめていない。
入力の切り替えは、コンボのCtrl+Space（F + G）でもできる。

ZMKのコンボは、いちばん上で有効なレイヤーで動くかを決めるので、レイヤーの一覧を
持つコンボ（コメントアウト、`` ` ``、`=`、戻る / 進む）にはANDROIDも入れている。

目印のレイヤーは、ZMKでは電源を切ると消える。そのため、起動したときに
保存されているBTプロファイルを見て、目印を戻す（`src/profile_layers.c`、
キーマップの `profile_layers`）。電源スイッチで入れ直したときやソフトオフ
から起こしたときも、Windowsのプロファイルならそのまま Windows の
キーになる。目印を手動で切り替えるキーはない（BTプロファイルのキーの
2回押しで、モニターを切り替えずに目印だけ合わせられる）。

番号は右手のoverlay（スワイプの切り替え）と、`nickey44a_r.conf` の
LEDのレイヤーの色でも使っているので、変えるときは合わせて直す。

### モニターの切り替え

1台のモニターを、Mac（USB-C）とWindows（HDMI）で共用している。BTプロファイルの
キーで、キーボードと一緒にモニターの入力も切り替える。

| キー（FUNCTION_BT） | 1回押し | 2回押し |
|---|---|---|
| BT0（Mac） | プロファイルを切り替えてから、F19を送る | キーボードだけ切り替える |
| BT3 / BT4（Windows） | F18を送ってから、プロファイルを切り替える | キーボードだけ切り替える |
| BT1 / BT6（iPad）、BT2（Android）、BT5（2台目のMac） | キーボードだけ切り替える | - |

- キーボードはF18とF19を送るだけで、切り替えはMac側の常駐プログラム（自作。
  このリポジトリには入れていない）が行う。Windows側には何も入れていない。
- ZMKはプロファイルを切り替えても、前の機器との接続を切らない。そのため
  Macは、Bluetoothの接続だけではどちらの機器が使われているか分からないので、
  キーで知らせる。F18は、まだつながっているMacに、切り替える前に送る。
  F19は、Macに切り替えてから送る。どちらも、キーが確実にMacに届くよう、
  マクロの中で少し待つ（`bt_win`、`bt_mac` マクロ）。
- 2回押しは、Macの内蔵ディスプレイやWindowsの画面で少し作業するとき用。

Mac側の常駐プログラムがすること:

- F18とF19を、macOSのグローバルホットキーとして登録している（Carbonの
  `RegisterEventHotKey`）。受け取るのはこの2つのキーだけで、ほかのキー入力は
  見ない。
- F18: DDC/CIでモニターの入力をHDMIに切り替え（`m1ddc`）、Macの画面を内蔵
  ディスプレイを主にしたミラーにし（`displayplacer`）、音声を内蔵スピーカーに
  する（`switchaudio-osx`）。モニターは表示していない入力も「つながっている」と
  伝え続けるので、そのままだとMacは、Windowsを表示しているモニターにも
  ウィンドウを置いてしまう。
- F19: 入力をUSB-Cに戻し、F18の前の画面配置と音声出力に戻す。
- 画面がスリープしている間にキーが来たら、画面が起きてから切り替える。
  スリープ中はmacOSが画面構成の変更を受け付けず、どちらの画面にも何も
  映らなくなることがあった。
- 前は、モニターの入力を定期的に読んで、Mac側の構成を合わせていた。
  しかし、Macの画面がスリープするとモニターが自動でHDMIに移り、それを
  Windowsへの切り替えと取り違えたので、キーが来たときだけ切り替える
  ようにした。

### Windows JISの記号

JIS配列のWindowsでは、同じキーでも出る記号が違う（`@` や `[` など）。
NUMの記号のうち位置が違う11個と、コンボの `` ` `` と `=` は、
WIN_JISが有効なときにJIS用のキーを送る。以前はNUMの写しのNUM_JISを
別に持っていたが、レイヤーで送るキーを選ぶ仕組み（下の「MOUSEレイヤーの
Mac / Windows切り替え」と同じ）にまとめた。NUMを直せば両方に効く。

### tomkeyから動かしたキー

Nickey44A-PADには、tomkeyにある内側の列と最下段がなく、代わりに外側の列が
ある。Bの右（30）とNの左（31）はトラックパッドの下でスイッチがないため
`&none` にしてあり、使えるキーは42個。

| キー | Nickey44A-PADでの位置 |
|---|---|
| Opt / Ctrl / Cmd | 左外側の上 / 中 / 下 |
| `;`（長押しでFUNCTION_BT） | 右外側の上（Pの右、11） |
| `-`（長押しでShift） | 右親指の外側（43） |
| `'` | 右ホーム段の小指（Lの右、22） |
| Del | 右下段の小指（36） |
| F2 / F7 | 右外側の中 / 下（23 / 37） |
| Ctrl+Space | コンボ F + G |
| `` ` `` | コンボ J + K |

- tomkeyのSCROLLレイヤーとエンコーダーは削除した。スクロールは
  両パッドの2本指で行う。

### MOUSEレイヤーのMac / Windows / iPad / Android切り替え

MOUSEレイヤー（右親指のLANG1を長押し）のキーのうち、機器によって
ショートカットが違うものは、どれでも同じ操作になるように、WIN、
IPAD、ANDROIDのどれが有効かで送るキーを変える。

| キー | 操作 | Mac | Windows | iPad | Android |
|---|---|---|---|---|---|
| W / R | 文書の先頭 / 末尾 | `Cmd+↑` / `Cmd+↓` | `Ctrl+Home` / `Ctrl+End` | Macと同じ | Windowsと同じ |
| C / V | 左 / 右の仮想デスクトップ | `Ctrl+←` / `Ctrl+→` | `Win+Ctrl+←` / `Win+Ctrl+→` | ホーム画面（`Cmd+H`） / 直前のアプリ（`Cmd+Tab`） | ホーム画面（`Meta+H`） / 直前のアプリ（`Alt+Tab`） |
| Q / A | ページの先頭 / 末尾 | `Home` / `End` | 同じ | 同じ | 同じ |
| U / I | 左 / 右のタブ | `Ctrl+Shift+Tab` / `Ctrl+Tab` | 同じ | 同じ | 同じ |

コンボも同じように、機器に合わせて送るキーを変える。

| コンボ | 操作 | Mac | Windows | iPad | Android |
|---|---|---|---|---|---|
| D + F | コメントアウト | `Cmd+/` | `Ctrl+/` | Macと同じ | Windowsと同じ |
| Z + X / X + C | 戻る / 進む | `Cmd+←` / `Cmd+→` | `Alt+←` / `Alt+→` | Macと同じ | Windowsと同じ |

iPadはMacと、AndroidはWindowsと同じキーで同じ操作になるので、機器ごとに
キーを変えるのは、違うものがあるところだけ（MOUSEのC / V、画面キャプチャ、
左パッドの左右）。

Q / Aは、ブラウザではどちらでもページの先頭 / 末尾に移る。文字の入力中は、
Windowsでは行頭 / 行末への移動になる。

切り替えは、mod-morphのレイヤー版として書いた `zmk,behavior-layer-morph`
（`src/behavior_layer_morph.c`）で行う。レイヤーは増やしていない。

### Reset と Boot

ResetとBootは、FUNCTION_BTとは別のSYSTEMレイヤーに置いてある。SYSTEMは、
`;`（FUNCTION_BT）とLANG2（NUM）を両方押している間だけ有効になる（ZMKの
conditional layer。押す順はどちらでもよい）。両手を使うので、うっかり
入らない。SYSTEMの間はLEDが赤くなる。電源オフとBT_CLR（今のプロファイルの
ペアリングを消す）もSYSTEMにある。

ResetとBootは、押したキーがある側にだけ効く（ZMKの仕様）。左右とも外側の
列の中と下に、左右対称に置いてある。右手の外側の上は `;`（11）なので
使わない。BT_CLRは右手の下段の中央（`,` の位置、34）。

| | Reset（再起動） | Boot（ブートモード） |
|---|---|---|
| 左手に効く | 左外側の中（12） | 左外側の下（24） |
| 右手に効く | 右外側の中（23） | 右外側の下（37） |

FUNCTION_BTの左外側の列は、ふだんの修飾キー（Alt・Ctrl・Cmd。Windowsでは
Alt・Win・Ctrl）のまま。`Ctrl+F5` や `Alt+F4` は、どの順で押しても打てる。
以前はFUNCTION_BTに置いていたが、`;` を先に押してから修飾キーを押すと
ResetやBootになってしまうので、SYSTEMに分けた。

### 画面キャプチャ

FUNCTION_BTのF12の右（Cの位置、27）は、つないでいる機器に合わせて画面キャプチャの
キーを送る（`screenshot`。WINとANDROIDを見るlayer morph）。

| 機器 | 送るキー | 撮る範囲 |
|---|---|---|
| Mac・iPad | `Cmd+Shift+4` | 選んだ範囲（iPadは撮ったあとに編集画面） |
| Windows | `Win+Shift+S` | 選んだ範囲 |
| Android | `Meta+Ctrl+S` | 画面全体（範囲を選ぶキーがない） |

### キーマップの編集

`config/nickey44a.keymap` を直接編集する。編集したら、keymap-drawerで
図を作り直す。

```sh
uvx --from keymap-drawer keymap -c keymap_drawer.config.yaml parse -z config/nickey44a.keymap -o keymap-drawer/nickey44a.yaml
uvx --from keymap-drawer keymap -c keymap_drawer.config.yaml draw -j config/nickey44a.json -s MAC WIN WIN_JIS NUM FUNCTION_BT MOUSE AUTO_MOUSE SYSTEM -o keymap-drawer/nickey44a.svg keymap-drawer/nickey44a.yaml
```

独自のbehaviorを図でどう表示するかは、`keymap_drawer.config.yaml` の
`raw_binding_map` で決める。図に入れるレイヤー（`-s`）は、GitHub Actionsで
図を作る `.github/workflows/draw.yml` の `draw_args` とそろえる。

## トラックパッド

ジェスチャの一覧と処理の流れは [dual-tps43.md](dual-tps43.md) にある。
このフォークで変えたのは次の点。

- 左右とも、ビルドガイドどおり切り欠きを右にして取り付ける。向きは
  `boards/shields/nickey44a/nickey44a_r.overlay` の先頭にある
  `RIGHT_PAD_MOUNT` と `LEFT_PAD_MOUNT` で切り替えられる。左パッドの補正も
  右手で行うので、向きを変えたときは右手だけ書き込めばよい。
- スクロールは、ホストのナチュラルスクロールをオンにしたとき（Windowsでは
  マウスのスクロール方向を逆にしたとき）に、中身が指について動く向き。
- 右パッドに触れると、AUTO_MOUSEに800 ms入る。その間は、右親指のLANG1と
  Enterが左クリック、右親指の外側（`-`）が右クリック、Spaceの長押しが
  MOUSE_SLOWになる。BackSpaceはそのままBackSpaceで、押すとAUTO_MOUSEを
  抜ける。MOUSEレイヤーの右クリックも同じ位置。
- 左パッドは、2本指の上下でタブ移動（指を上へで右のタブ）、左右で
  仮想デスクトップの移動（指を右へで左のデスクトップ。iPadとAndroidでは何もしない）。
  長押しで左ボタンを押したままにでき、ドラッグに使う。

右パッドの2本指の左右は、普段は横スクロールで、キーを押している間だけ
スワイプになる。タブ移動と仮想デスクトップは左パッドだけにした
（2026-11-24。それまでは、右パッドの普段の左右が戻る / 進む、Spaceを
押しながらがタブ移動、LANG2を押しながらが仮想デスクトップで、左パッドの
左右は横スクロールだった。タブ移動が左右のパッドで重なっていた）。
同じ操作がパッドの2か所に出ないようにしている。

| そのときの状態 | Mac | Windows | iPad | Android |
|---|---|---|---|---|
| 通常 | 横スクロール | 同じ | 同じ | 同じ |
| MOUSE_SLOW（パッドに触れてSpaceを長押し） | 戻る / 進む（`Cmd+[` / `Cmd+]`） | Browser Back / Forward | Macと同じ | Windowsと同じ（Androidの「戻る」「進む」になる） |
| NUM（LANG2を長押し） | アプリスイッチャー（`Cmd+Tab`） | アプリスイッチャー（`Alt+Tab`） | Macと同じ | Windowsと同じ（Android 14以降のタブレット） |

アプリスイッチャー：LANG2を押しながら2本指で左右に動かすと、`Cmd+Tab`
（Windowsでは `Alt+Tab`）でアプリスイッチャーが開き、指を置いている間は
`Cmd`（`Alt`）を押したままにする。そのまま左右に動かすと選択が1つずつ動き
（指を左へで右、右へで左）、指を離すと選んだアプリに切り替わる。1回押す
だけだと直前のアプリとの行き来になるが、これならもっと前のアプリにも行ける。

向きはMacBookと同じで、指を右へで「戻る」。macOSはBrowser Back / Forwardの
キーを無視するので、Macでは `Cmd+[` / `Cmd+]` を送る。

左パッドで上下と左右の両方をスワイプにするため、タッチスワイプの
モジュールに `pass-swipe-axis` を追加した。1つ目（タブ）がその軸を
次へ通すので、2つ目（仮想デスクトップ）も上下と左右の両方を見て、
斜めの動きで両方が反応しないようにできる。通した軸は最後に捨てる。

普段の左右を横スクロールにできるように、タッチスワイプのモジュールで、
通常時のキー（`left-keycode` / `right-keycode`）を設定しないと、
上書きのレイヤーが有効でない間は横スクロールをそのまま通すようにした。

2つ目のレイヤーでも送るキーを変えられるように、タッチスワイプの
モジュール（`modules/zmk-input-processor-touch-swipe`）に
`second-override-layers` を追加した。iPadのアプリスイッチャーのために、
キーを押したままにして続けて送る `second-override-hold-keycode` と
`second-override-repeat-threshold` も追加した。

### ピンチで拡大・縮小

右パッドで2本指を広げると拡大、縮めると縮小のキーを送る。

| 機器 | 拡大（広げる） | 縮小（縮める） |
|---|---|---|
| Mac・iPad | `Cmd+=` | `Cmd+-` |
| Windows（WIN・WIN_JIS）・Android | `Ctrl` + テンキーの `+` | `Ctrl` + テンキーの `-` |

標準の大きさに戻すには、右パッドに触れてからSpaceを長押しし（MOUSE_SLOW）、
押したまま2本指でタップする。Mac・iPadは `Cmd+0`、Windows・Androidは `Ctrl+0` を
送る（`0` はUSとJISで同じキー）。このときは右クリックにならない。Spaceを
押しながらの右クリックは普通の2本指タップと同じだったので、そこに入れた。

ホストからはマウスに見えるので、MacBookのような滑らかな拡大ではなく、
ブラウザなどの拡大・縮小のキーを段階的に送る。Windowsでテンキーを使うのは、
USとJISで同じキーになり、JIS用に分けずに済むから。

- パッドのピンチの検出（ドライバーの `zoom;`）を、右パッドだけでオンにした。
  ドライバーは、広げるとプラス、縮めるとマイナスの値を `INPUT_REL_MISC` で
  出す。2026-11-24に確認用のファームウェア（USBにログを出すもの）で測った
  ところ、1回のピンチで10〜20だった。2本指のスクロール、スワイプ、タップは、
  ピンチと取り違えなかった（スワイプの出だしに+1が1回だけ混ざった）。
- この値をためて、6ごとにキーを1回送る（`src/input_processor_pinch_zoom.c`、
  overlayの `tps43_pinch_zoom` と `tps43_pinch_zoom_win` の `threshold`）。
  1回のピンチで2〜3段変わる。
- 指を寄せ切ったときや片方の指を離したとき、パッドは残った指の位置の
  大きな移動（100前後）をカーソルの移動として出す。そのため、ピンチした
  タッチでは、指を離すまでカーソルを動かさない。
- リセットは、同じprocessorの `reset-layer`（MOUSE_SLOWの1）と
  `reset-keycode` で設定する。2本指タップ（ドライバーの `INPUT_BTN_1`）の
  押す・離すを両方止める。

ZMKのinput-listenerは、processorが `ZMK_INPUT_PROC_STOP` を返して入力を
止めても、それが効くのはレイヤーで切り替えていない普段の処理だけで、
WINのレイヤーの処理では入力をそのまま使ってしまう（2026-11-24に、ZMKの
`input_listener.c` で確認）。そのため、Windowsでは、Spaceを押しながらの
スワイプやLANG2を押しながらのスワイプで横スクロールも一緒に出て、ピンチの
あとにカーソルが飛んでいたはず。タッチスワイプとピンチのprocessorは、
止める入力をlistenerが無視する種類（値0のmiscellaneous）に書き換えてから
止めるようにした。

## 電源

### 電池残量の表示

`;`（FUNCTION_BT）を押したままVを押すと、右手のLEDに、右手、左手の順で
電池残量を2秒ずつ色で表示する。

| 色 | 残量 |
|---|---|
| 緑 | 60%以上 |
| 黄 | 30〜59% |
| 赤 | 30%未満 |
| マゼンタ | 取得できない（左手とつながっていないときなど） |

- 電源を入れたときに光る色も、同じ基準。
- 左手のLEDにも、同時に左手の残量が出る。
- `;` を押したままだと、2つの表示の間にFUNCTION_BTレイヤーの色（水色）が
  挟まる。Qを押したら `;` も離すと見やすい。
- 残量は電池の電圧から推定していて、単4のNi-MH電池向けに合わせてある
  （`boards/shields/nickey44a/nickey44a.dtsi`）。Ni-MHは使っている間の
  電圧の変化が小さいので、目安として見る。
- しきい値は `config/nickey44a_r.conf` と `config/nickey44a_l.conf` の
  `CONFIG_RGBLED_WIDGET_BATTERY_LEVEL_*` で、左右同じ値にしておく。

### ソフトオフ

- **切る**：`;` とLANG2を押したまま（SYSTEM）、左外側の上（位置0）を
  1秒以上押してから離す。左右とも切れ、LEDも消える。
- **起こす**：左右それぞれの電源スイッチを、切ってから入れ直す。
  キーを押しても起きない。
- XIAOのリセットボタンでも起きる。ただしXIAOの小さな部品で、2回続けて
  押すとブートモードに入るので、ふだんは電源スイッチを使う。

最初はQの左隣とPの右のキーで起きるようにしていた。持ち運び用のケースの
中で押されて起きてしまうため、キーでは起きないようにした。ソフトオフ中は
チップが止まっていて、ダブルタップや組み合わせを判定できない。

ZMK標準の `&soft_off` は、左手を押した瞬間に切る。キーが左手にあると、
左手が先に切れて「離した」が右手に届かない。そこで、左右とも1秒押して
離したときに切れる `soft_off_hold`（ノード名 `so_hold`）を定義した。
ノード名は、左右の間で送れる8文字以内にしてある。

LEDは、そのときのレイヤーの色で光ったまま残っていた。ウィジェットは
自動スリープのときにしかLEDを消さず、チップは電源オフ中も出力ピンの
状態を保つためである。電源を落とす直前にLEDを消す処理を
`src/soft_off_leds.c` に足した。

### 自動スリープ

作者の設定のまま。2時間操作しないと深いスリープに入り、キーを押すと起きる。

### ソフトオフと電源スイッチの使い分け

- 電源スイッチで切ると、電池が回路から切り離されて電池は減らない。
  ソフトオフでも、チップ、電池電圧の測定回路、電源回路、パッドの待機で
  わずかに電流が流れる（実測はしていない）。何日も使わないときは
  電源スイッチで切る。
- 起こすには電源スイッチを使うので、切るのもスイッチで十分。ソフトオフは、
  キー操作1回で左右とも切りたいときに使う。
- BTプロファイルなどの設定は、変えてから1分後に保存される。それより前に
  切ると、その変更は保存されない。どちらの切り方でも同じで、設定が
  壊れることはない。
